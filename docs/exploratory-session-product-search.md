# Exploratory Testing Session – Product Search
## Session information
- Application: Automation Exercise
- Area: Product search
- Browser: Google Chrome 155.0.8059.85, 64-bit
- Ad blocker: Disabled
- Test date: 21 October 2026
- Duration: 30 minutes
- Tester: Katarzyna Chardy

## Charter
Explore product search behaviour for valid, invalid and unexpected input.
Verify result relevance, input normalisation, empty-result feedback and
the HTTP requests generated by the search form.

## Test approach
The session combined exploratory UI testing with request inspection in
Chrome DevTools Network.

For each input, the following elements were observed:

- generated request and query parameter,
- HTTP status,
- displayed products,
- feedback presented to the user,
- value retained in the search field.

## Session notes
| Input | HTTP observation | Application behaviour |
|---|---|---|
| `jeans` | `GET /products?search=jeans`, `200 OK` | Three matching products were displayed. The search term remained in the field. |
| `JEANS` | `GET /products?search=JEANS`, `200 OK` | The same three matching products were displayed. Search was case-insensitive for this input. |
| `jean` | `GET /products?search=jean`, `200 OK` | The same products as for `jeans` were displayed, indicating partial matching. |
| `blue` | `GET /products?search=blue`, `200 OK` | Seven products containing the search term were displayed. The term remained in the field. |
| `abc` | `GET /products?search=abc`, `200 OK` | No products and no empty-result message were displayed. The term remained in the field. |
| `123` | `GET /products?search=123`, `200 OK` | No products and no empty-result message were displayed. The term remained in the field. |
| Long alphabetic string | `GET /products?search=[long value]`, `200 OK` | No products and no empty-result message were displayed. The value remained in the field but was not fully visible because of the field width. |
| Empty input | Search submitted without a meaningful term | The complete product catalogue was displayed and the search field was empty. |
| Whitespace-only input | Search submitted using spaces only | The complete product catalogue was displayed and the search field was cleared. |
| Leading spaces followed by `jeans` | `GET /products?search=%20%20%20jeans`, `200 OK` | No products and no empty-result message were displayed. The spaces were preserved in the query. |
| `jeans` followed by trailing spaces | `GET /products?search=jeans`, `200 OK` | Three matching products were displayed. The trailing spaces were removed from the query and the field. |

## Findings
### Search matching

The tested search was case-insensitive and supported partial matches.
`jeans`, `JEANS` and `jean` returned the same relevant products.

### Empty-result feedback

No message was displayed when a search returned no matching products.
The behaviour was reproduced using:

- an unknown alphabetic value,
- a numeric value,
- a long alphabetic value,
- a valid product term preceded by spaces.

This confirms the behaviour documented in
[BUG-006 – No feedback is displayed when search returns no results](https://github.com/kchardy/tester-portfolio-automation-exercise/issues/6).

### Whitespace handling

Whitespace handling was inconsistent:

- whitespace-only input was treated as an empty search,
- trailing spaces were removed,
- leading spaces were preserved and caused a valid term to return no results.

This may cause false empty results when a user accidentally enters spaces
before a product name. The expected normalisation rules should be confirmed
before reporting it as a separate defect.

### Search state

For non-empty searches, the submitted term remained visible in the search
field. To return to the complete catalogue, the user had to clear the field
and submit again or select **Products** from the navigation menu.

## Risks and user impact
- A blank result area does not tell the user whether no products exist,
  the search is still loading or an error occurred.
- Inconsistent trimming can cause an existing product to appear unavailable.
- Long values remain in the field but are only partially visible.

## Follow-up testing
Recommended additional exploration:

- special characters,
- Polish and other Unicode characters,
- multiple spaces inside a product name,
- search behaviour on a mobile viewport,
- maximum accepted input length,
- browser back and forward navigation after several searches.

## Session conclusion
The core search function returned relevant results for valid terms and
handled letter case consistently in the tested examples. The main usability
risk is the lack of empty-result feedback. Inconsistent handling of leading
and trailing whitespace should also be investigated further.
